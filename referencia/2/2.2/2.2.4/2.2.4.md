# 2.2.4. Módulo 4 / Integrante 4 (RODRIGUEZ)

> **Módulo 4 – Interacción Social y Notificaciones.** Atributos dominantes: **escalabilidad de escritura** y **disponibilidad**. Es el módulo que recibe el mayor volumen de operaciones por segundo y donde se admite explícitamente consistencia eventual a cambio de capacidad.

### Escalabilidad

**ESC-M4-01 — Avalancha de interacciones sobre un video viral**
| Parte | Contenido |
|---|---|
| Fuente | Usuarios finales. |
| Estímulo | Un video recibe 50,000 reacciones y 8,000 comentarios por minuto durante 30 minutos. |
| Artefacto | Servicio de interacciones y contadores (M4). |
| Entorno | Pico de carga extremo sobre una sola entidad (*hot partition*). |
| Respuesta | Las reacciones se escriben en un buffer en memoria y se agregan en ventanas de 5 segundos antes de persistirse; los contadores se fragmentan en múltiples claves para evitar contención sobre una fila única; los comentarios se escriben de forma asíncrona. |
| Medida | **Latencia de confirmación de reacción ≤ 100 ms en p95** durante todo el pico. 0 pérdidas de interacción. Contador público con desfase máximo de 10 segundos. |

**ESC-M4-02 — Notificación masiva de un creador grande**
| Parte | Contenido |
|---|---|
| Fuente | Creador con 2,000,000 de seguidores. |
| Estímulo | Publica un video; corresponde notificar a sus seguidores. |
| Artefacto | Motor de notificaciones (M4). |
| Entorno | Operación normal. |
| Respuesta | El abanico de salida (*fan-out*) se procesa de forma asíncrona por lotes, con limitación de tasa hacia FCM/APNs, priorizando a los seguidores con mayor afinidad y respetando los horarios de silencio de cada destinatario. |
| Medida | **95% de las notificaciones entregadas en menos de 3 minutos.** 0 bloqueos del proveedor de push por exceso de tasa. Sin impacto en la latencia de otras operaciones de M4. |

### Disponibilidad

**ESC-M4-03 — Caída del servicio de mensajería directa**
| Parte | Contenido |
|---|---|
| Fuente | Componente interno. |
| Estímulo | El servicio de DM queda no disponible durante 20 minutos. |
| Artefacto | Servicio de mensajería (M4). |
| Entorno | Falla de un componente interno. |
| Respuesta | El resto de funcionalidades sociales (reacciones, comentarios, seguimientos) sigue operando porque están desplegadas de forma independiente; los mensajes enviados desde el cliente se encolan localmente y se reenvían al restablecerse el servicio. |
| Medida | **0% de impacto en el feed y en las interacciones.** 100% de mensajes encolados entregados tras la recuperación. Recuperación en menos de 10 minutos. |

**ESC-M4-04 — Falla del bus de eventos**
| Parte | Contenido |
|---|---|
| Fuente | Infraestructura (Kafka). |
| Estímulo | Un *broker* del clúster falla. |
| Artefacto | Bus de eventos + productores de M4. |
| Entorno | Falla de infraestructura. |
| Respuesta | La replicación con factor 3 y la elección de un nuevo líder de partición mantienen el servicio; los productores reintentan con reserva exponencial; los consumidores retoman desde el último desplazamiento confirmado. |
| Medida | **0 eventos perdidos.** Retraso de consumo recuperado en menos de 10 minutos. Sin impacto perceptible para el usuario. |

### Performance

**ESC-M4-05 — Carga del panel de comentarios**
| Parte | Contenido |
|---|---|
| Fuente | Usuario final. |
| Estímulo | Abre los comentarios de un video con 200,000 comentarios. |
| Artefacto | Servicio de comentarios (M4). |
| Entorno | Operación normal. |
| Respuesta | Se devuelven los 20 comentarios más relevantes mediante paginación por cursor sobre un índice precalculado de relevancia; las respuestas se cargan bajo demanda. |
| Medida | **Primera página en ≤ 200 ms en p95.** Páginas siguientes en ≤ 150 ms. Uso de memoria del cliente constante independientemente del volumen total. |

### Seguridad / Privacidad

**ESC-M4-06 — Contacto no deseado**
| Parte | Contenido |
|---|---|
| Fuente | Usuario con intención de acoso. |
| Estímulo | Intenta enviar mensajes directos y comentarios reiterados a un usuario que lo bloqueó. |
| Artefacto | Servicio de mensajería y de comentarios (M4). |
| Entorno | Operación normal. |
| Respuesta | La verificación de bloqueo se aplica en la escritura y en la lectura; ninguna de las dos cuentas ve contenido de la otra; los intentos reiterados alimentan el sistema de detección de acoso. |
| Medida | **100% de mensajes y comentarios bloqueados.** La verificación agrega menos de 10 ms a la latencia de la operación. Aplicación efectiva en menos de 1 segundo desde que se registra el bloqueo. |

### Modificabilidad

**ESC-M4-07 — Nuevo tipo de reacción**
| Parte | Contenido |
|---|---|
| Fuente | Equipo de producto. |
| Estímulo | Incorporar reacciones diferenciadas además del "me gusta". |
| Artefacto | Modelo de interacciones (M4). |
| Entorno | Tiempo de diseño. |
| Respuesta | El modelo de datos almacena el tipo de reacción como atributo desde el diseño inicial, de modo que agregar un tipo no requiere migración de esquema ni cambios en los consumidores de eventos. |
| Medida | Menos de 4 días-persona. 0 migraciones de datos. M3 y M5 continúan funcionando sin cambios, ignorando los tipos que no conocen. |
