# 2.2.1. Módulo 1 / Integrante 1 (CHUNG)

> **Módulo 1 – Identidad, Cuentas y Perfiles.** El atributo dominante es **seguridad**. Siguiendo el criterio de diferenciación por tipo de amenaza, se especifican escenarios distintos para robo de credenciales, secuestro de sesión, escalamiento de privilegios y fuga de datos personales, porque cada uno exige tácticas diferentes.

Todos los escenarios usan las seis partes del formato: **fuente del estímulo, estímulo, artefacto, entorno, respuesta y medida de la respuesta**.

### Seguridad

**ESC-M1-01 — Ataque de fuerza bruta sobre credenciales**
| Parte | Contenido |
|---|---|
| Fuente | Atacante externo no autenticado, operando desde una botnet distribuida. |
| Estímulo | 10,000 intentos de inicio de sesión por minuto contra cuentas existentes, usando listas de contraseñas filtradas. |
| Artefacto | Servicio de autenticación (M1). |
| Entorno | Operación normal. |
| Respuesta | El sistema limita la tasa por IP, por cuenta y por huella de dispositivo; exige CAPTCHA tras 5 fallos; bloquea la cuenta por 15 minutos tras 10 fallos; notifica al titular; y registra el intento en la bitácora de seguridad. |
| Medida | 0 cuentas comprometidas. Menos de 0.1% de usuarios legítimos afectados por falsos positivos. Detección y mitigación activa en menos de 60 segundos desde el inicio del ataque. |

**ESC-M1-02 — Secuestro de sesión por robo de refresh token**
| Parte | Contenido |
|---|---|
| Fuente | Atacante que obtuvo un *refresh token* válido desde un dispositivo comprometido. |
| Estímulo | Uso del token robado para obtener un nuevo par de tokens. |
| Artefacto | Servicio de emisión de tokens (M1). |
| Entorno | Operación normal. |
| Respuesta | La rotación detecta la reutilización de un token ya consumido, revoca toda la familia de tokens del dispositivo, cierra las sesiones asociadas y notifica al titular por push y correo. |
| Medida | Revocación efectiva en menos de 5 segundos desde la detección. 100% de las familias de tokens comprometidas revocadas. |

**ESC-M1-03 — Escalamiento de privilegios**
| Parte | Contenido |
|---|---|
| Fuente | Usuario autenticado con rol `USER`. |
| Estímulo | Invoca directamente un endpoint administrativo (`/v1/admin/...`) manipulando el token o la ruta. |
| Artefacto | Gateway + servicio de autorización (M1). |
| Entorno | Operación normal. |
| Respuesta | La autorización se evalúa en el gateway y nuevamente en el servicio destino; la petición se rechaza con 403, se registra con actor, recurso y `trace_id`, y se genera una alerta si el mismo actor repite el intento. |
| Medida | 100% de intentos rechazados. 0 accesos no autorizados en pruebas de penetración. Registro disponible en menos de 30 segundos. |

**ESC-M1-04 — Acceso interno indebido a datos personales**
| Parte | Contenido |
|---|---|
| Fuente | Empleado con acceso a la consola de moderación. |
| Estímulo | Consulta los datos personales de un usuario sin un caso de moderación abierto que lo justifique. |
| Artefacto | Consola interna + bitácora de auditoría (M1). |
| Entorno | Operación normal. |
| Respuesta | El acceso exige un identificador de caso; sin él se deniega. Todo acceso queda registrado de forma inmutable y se genera un reporte semanal de accesos sin caso asociado para el oficial de cumplimiento. |
| Medida | 100% de accesos a datos personales trazables a un actor y un motivo. Reporte de anomalías disponible en menos de 24 horas. |

### Disponibilidad

**ESC-M1-05 — Caída del proveedor de identidad federada**
| Parte | Contenido |
|---|---|
| Fuente | Proveedor externo (Google / Apple). |
| Estímulo | El servicio OIDC del proveedor deja de responder durante 30 minutos. |
| Artefacto | Servicio de autenticación (M1). |
| Entorno | Falla de una dependencia externa. |
| Respuesta | El *circuit breaker* abre tras 5 fallos consecutivos; la interfaz oculta temporalmente ese método de inicio de sesión y ofrece los alternativos; las sesiones ya activas no se ven afectadas porque la validación del token es local por JWKS. |
| Medida | 0% de impacto en usuarios con sesión activa. Menos del 8% de inicios de sesión afectados. Recuperación automática en menos de 2 minutos tras restablecerse el proveedor. |

### Modificabilidad

**ESC-M1-06 — Incorporar un nuevo método de autenticación**
| Parte | Contenido |
|---|---|
| Fuente | Equipo de desarrollo, a solicitud de negocio (ingreso a Colombia). |
| Estímulo | Agregar autenticación por WhatsApp OTP. |
| Artefacto | Servicio de autenticación (M1). |
| Entorno | Tiempo de diseño y desarrollo. |
| Respuesta | Se implementa un nuevo adaptador de la interfaz `AuthProvider` sin modificar el núcleo de emisión de tokens ni los módulos consumidores. |
| Medida | Menos de 3 días-persona. 0 cambios en M2–M5. 0 despliegues coordinados con otros equipos. |

### Usabilidad

**ESC-M1-07 — Registro sin abandono**
| Parte | Contenido |
|---|---|
| Fuente | Usuario nuevo, desde un celular de gama media en red móvil. |
| Estímulo | Decide crear una cuenta. |
| Artefacto | Flujo de registro (M1) + app. |
| Entorno | Operación normal, primera instalación. |
| Respuesta | El sistema solicita únicamente celular o correo, verifica por OTP con autocompletado del código y difiere el resto de datos del perfil a un momento posterior. |
| Medida | Mediana del tiempo de registro menor a 60 segundos. Tasa de finalización superior al 85% en pruebas con 20 usuarios. |
