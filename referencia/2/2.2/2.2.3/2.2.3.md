# 2.2.3. Módulo 3 / Integrante 3 (RENGIFO)

> **Módulo 3 – Feed, Recomendación y Búsqueda.** Atributo dominante: **performance (latencia extremo a extremo)**, con **disponibilidad con degradación controlada** como segundo eje. El feed es la superficie donde una décima de segundo se traduce en minutos de permanencia y, por lo tanto, en ingreso publicitario.

### Performance

**ESC-M3-01 — Latencia de generación del feed en operación normal**
| Parte | Contenido |
|---|---|
| Fuente | Usuario final. |
| Estímulo | Solicita una página del feed "Para ti". |
| Artefacto | Servicio de feed: generación de candidatos + ranking (M3). |
| Entorno | Operación normal. |
| Respuesta | El sistema recupera candidatos, los puntúa, aplica diversidad, solicita el anuncio a M5 e hidrata metadatos en M2. |
| Medida | **Latencia del servicio ≤ 150 ms en p95 y ≤ 300 ms en p99**, medida en el gateway. Latencia percibida por el usuario (apertura de app hasta primer video reproduciéndose) **≤ 1.2 s en p95**. |

**ESC-M3-02 — Latencia bajo pico de tráfico**
| Parte | Contenido |
|---|---|
| Fuente | Base de usuarios. |
| Estímulo | El tráfico se multiplica por 5 en 10 minutos por un evento viral. |
| Artefacto | Servicio de feed y su caché (M3). |
| Entorno | Pico de carga no previsto. |
| Respuesta | El autoescalado incorpora réplicas; la caché de timelines precomputados absorbe la primera página de los usuarios activos; si la latencia del ranking supera su presupuesto, se activa el modo heurístico. |
| Medida | p95 se mantiene **por debajo de 400 ms** durante el pico. 0 errores 5xx atribuibles a saturación. Menos del 20% de las solicitudes servidas en modo degradado. |

**ESC-M3-03 — Continuidad del desplazamiento**
| Parte | Contenido |
|---|---|
| Fuente | Usuario final. |
| Estímulo | Desliza continuamente durante una sesión de 15 minutos. |
| Artefacto | Feed + cliente (M3, M2). |
| Entorno | Operación normal, red móvil variable. |
| Respuesta | La siguiente página se solicita al alcanzar el séptimo elemento y los siguientes dos videos se precargan parcialmente. |
| Medida | **Menos de 1 pantalla de carga visible por cada 100 deslizamientos.** 0 interrupciones de más de 1 segundo entre videos en el p95. |

### Disponibilidad

**ESC-M3-04 — Caída del servicio de ranking**
| Parte | Contenido |
|---|---|
| Fuente | Componente interno (servicio de ranking, por ejemplo tras desplegar una versión de reglas defectuosa). |
| Estímulo | El servicio de ranking deja de responder o excede su presupuesto de latencia. |
| Artefacto | Servicio de feed (M3). |
| Entorno | Falla de un componente interno. |
| Respuesta | El *circuit breaker* abre y el feed se sirve con el ordenamiento heurístico de respaldo (popularidad reciente + país + intereses declarados) desde una caché precomputada, con un indicador discreto en la interfaz. |
| Medida | **El usuario nunca recibe un error**: 100% de solicitudes atendidas. Latencia en modo degradado ≤ 200 ms en p95. Retorno automático al modo normal en menos de 60 segundos tras la recuperación. |

**ESC-M3-05 — No disponibilidad del ad server**
| Parte | Contenido |
|---|---|
| Fuente | Módulo M5. |
| Estímulo | El ad server no responde dentro de los 80 ms asignados. |
| Artefacto | Etapa de post-procesamiento del feed (M3). |
| Entorno | Falla de un módulo dependiente. |
| Respuesta | La posición publicitaria se rellena con contenido orgánico; el fallo se contabiliza como pérdida de inventario y se alerta al equipo de monetización. |
| Medida | **0% de impacto en la latencia y en la disponibilidad del feed.** Alerta emitida en menos de 1 minuto. Pérdida de inventario cuantificada en el tablero de negocio. |

### Escalabilidad

**ESC-M3-06 — Crecimiento de la base de usuarios**
| Parte | Contenido |
|---|---|
| Fuente | Crecimiento del producto. |
| Estímulo | Los usuarios activos diarios pasan de 100,000 a 1,000,000. |
| Artefacto | Servicio de feed, caché e índice de candidatos (M3). |
| Entorno | Operación normal. |
| Respuesta | El servicio escala horizontalmente sin estado; la caché se particiona por usuario; el índice de candidatos se replica por región. |
| Medida | Se mantienen los objetivos de ESC-M3-01. **Costo de infraestructura por usuario activo no crece más de 15%** respecto de la línea base. |

### Modificabilidad

**ESC-M3-07 — Cambio de las reglas de ranking**
| Parte | Contenido |
|---|---|
| Fuente | Responsable de M3, a pedido del Gestor del Negocio. |
| Estímulo | Ajustar los pesos del ranking (por ejemplo, dar más peso a la cercanía regional durante una campaña local) o publicar una nueva versión del conjunto de reglas. |
| Artefacto | Servicio de ranking y su configuración (M3). |
| Entorno | Tiempo de ejecución, en producción. |
| Respuesta | La nueva versión de reglas se carga desde la configuración versionada, sin recompilar ni redesplegar el servicio; se activa primero para el 5% del tráfico; si el p95 o la tasa de finalización empeoran, se vuelve a la versión anterior. |
| Medida | **Cambio activo en menos de 5 minutos sin redespliegue.** Reversión en menos de 5 minutos. 0 cambios de código en los clientes y en los otros módulos. |

### Seguridad / Integridad del contenido

**ESC-M3-08 — Manipulación del feed por contenido fraudulento**
| Parte | Contenido |
|---|---|
| Fuente | Actor malicioso con una red de cuentas falsas. |
| Estímulo | Genera interacciones artificiales para posicionar un video en el feed. |
| Artefacto | Señales de ranking (M3) + detección de fraude (M5). |
| Entorno | Operación normal. |
| Respuesta | Las señales provenientes de cuentas marcadas como sospechosas se descartan del cálculo de ranking; el contenido se retira de la exploración de contenido nuevo y se deriva a revisión. |
| Medida | **Menos del 2% de las impresiones diarias atribuibles a manipulación detectada.** Detección en menos de 30 minutos desde el inicio del patrón anómalo. |
