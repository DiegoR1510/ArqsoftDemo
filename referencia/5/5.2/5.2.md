# 5.2. Módulo 2 / Integrante 2 (HIDALGO)

> **Módulo 2 – Contenido y Pipeline de Medios.** Para cada escenario: **escenario (código) → táctica → ADR** con las opciones de implementación. Las decisiones estructurales están en [4.2](../../4/4.2/4.2.md).

## T-M2-01 — Colas con prioridad, workers en paralelo y autoescalado por profundidad de cola

| | |
|---|---|
| **Escenario** | **ESC-M2-02** / ER-03: 8,000 videos en una hora; el 95% disponible en < 90 s. |
| **Táctica** | *Introducir concurrencia* (muchos workers en paralelo) + *programar recursos* (cola prioritaria) + *aumentar recursos* (autoescalado). |
| **Cómo se aplica** | Dos colas BullMQ: `transcode-priority` (contenido patrocinado y creadores grandes) y `transcode-standard`. Los workers `transcode-worker` toman primero de la prioritaria. El número de workers escala de 0 a 200 según la profundidad de la cola; la cola estándar usa instancias interrumpibles (*spot*) y, si su profundidad supera un umbral, se suman instancias bajo demanda. Las cuatro representaciones (1080p, 720p, 480p, 360p) se generan en paralelo. |
| **Dónde se ve** | Redis M2 (colas) y `transcode-worker` (6.2); autoescalado en 6.4. |

### ADR-T-M2-01 — Capacidad de transcodificación

| Opción | Ventajas | Desventajas |
|---|---|---|
| A. Flota fija dimensionada para el pico | Latencia estable. | Paga el pico todo el día (RN-05). |
| B. Workers bajo demanda con autoescalado | Costo proporcional a la carga. | El cómputo bajo demanda es caro a este volumen. |
| **C. Workers interrumpibles con respaldo bajo demanda + cola prioritaria** | Hasta 70% menos de costo; los trabajos son idempotentes, así que una interrupción solo cuesta reintentar. | Hay que manejar interrupciones. |

**Criterios.** Medida de ER-03, costo (RN-05). **Decisión:** **C**. **Sustento:** la transcodificación es el caso ideal para cómputo interrumpible (trabajos cortos, sin estado, reintentables); la cola prioritaria protege el contenido patrocinado, que tiene compromiso contractual. **Consecuencias:** el monitoreo distingue el retraso por falta de capacidad del retraso por falla.

## T-M2-02 — Caché de borde en la CDN y precarga del siguiente video

| | |
|---|---|
| **Escenario** | **ESC-M2-01**: primer fotograma ≤ 400 ms en p95. |
| **Táctica** | *Mantener múltiples copias de datos*. |
| **Cómo se aplica** | Los segmentos HLS se sirven desde la caché de CloudFront (punto de presencia en Lima) con vencimiento largo; la app precarga el primer segmento de los dos videos siguientes del feed. |
| **Dónde se ve** | CloudFront en 6.2 y 6.4. |

### ADR-T-M2-02 — Origen de los segmentos

| Opción | Ventajas | Desventajas |
|---|---|---|
| A. Servir desde S3 | Simple. | Latencia desde Lima a la región; egreso caro. |
| **B. CDN con caché larga para segmentos y corta para manifiestos + precarga en el cliente** | El primer segmento casi siempre ya está cerca o en el teléfono. | Consumo de datos de la precarga. |

**Decisión:** **B**, limitando la precarga a los dos siguientes videos para respetar el consumo de datos del espectador (SH-02). **Consecuencias:** la invalidación de caché ante una eliminación se hace por el manifiesto (vence rápido), no por los segmentos.

## T-M2-03 — Réplicas en tres zonas y trabajos idempotentes reintentables

| | |
|---|---|
| **Escenario** | **ESC-M2-04** / ER-08: disponibilidad de reproducción ≥ 99.95%; recuperación ≤ 3 min; 0 videos perdidos. |
| **Táctica** | *Redundancia activa* + *reintento*. |
| **Cómo se aplica** | `media-service` corre con réplicas activas en tres zonas detrás del balanceador; PostgreSQL M2 en Multi-AZ; S3 replica en varias zonas por diseño. Un trabajo de transcodificación interrumpido vuelve a la cola (BullMQ lo reintenta hasta 3 veces con espera exponencial) y produce los mismos archivos. |
| **Dónde se ve** | Vista de despliegue (6.4). |

### ADR-T-M2-03 — Tipo de redundancia

| Opción | Ventajas | Desventajas |
|---|---|---|
| A. Redundancia pasiva (réplica en espera) | Más barata. | Conmutar toma minutos. |
| **B. Redundancia activa (todas las réplicas atienden)** | Sin tiempo de conmutación: el balanceador solo deja de enviar tráfico a la zona caída. | Costo de mantener réplicas activas. |

**Decisión:** **B**. **Sustento:** solo B cumple los 3 minutos de recuperación. **Consecuencias:** mínimo dos réplicas siempre, aun en horas de baja demanda.

## T-M2-04 — Falla segura: ningún video sin clasificar se publica

| | |
|---|---|
| **Escenario** | **ESC-M2-05**: 0 videos publicados sin clasificar si el proveedor de moderación cae. |
| **Táctica** | *Prevención de excepciones* (llevar el sistema a un estado seguro). |
| **Cómo se aplica** | El video queda en estado `MODERATING` hasta recibir un veredicto. Si el clasificador no responde, el video pasa a la cola humana ordenada por alcance esperado y se informa al creador en ≤ 2 min. |
| **Dónde se ve** | `media-service` (componente `ModerationStep`) (6.2). |

### ADR-T-M2-04 — Qué hacer cuando la moderación automática no responde

| Opción | Ventajas | Desventajas |
|---|---|---|
| A. Publicar y moderar después | Mejor experiencia para el creador. | Contenido infractor visible y distribuido por el feed: irreversible. |
| **B. Bloquear hasta clasificar (falla segura)** | Ningún contenido sin clasificar circula. | Demora para el creador mientras dure la caída. |
| C. Publicar de inmediato solo a creadores con historial limpio | Menos demora. | Requiere un modelo de reputación que en F1 no existe. |

**Decisión:** **B** en F1, con C como evolución. **Sustento:** el riesgo es asimétrico: la demora es molesta pero reversible; contenido gravemente infractor distribuido no lo es (RL-03). **Consecuencias:** la capacidad de moderación humana debe absorber el atraso en ≤ 4 h.

## T-M2-05 — URL firmada de vida corta para reproducir

| | |
|---|---|
| **Escenario** | **ESC-M2-06**: 100% de intentos con URL vencida o ajena rechazados. |
| **Táctica** | *Limitar exposición* + *autenticar actores*. |
| **Cómo se aplica** | El bucket es privado. `media-service` firma la URL de CloudFront (5 min, ligada a la sesión) solo si el usuario puede ver el video (consulta a M4 para cuentas privadas). |
| **Dónde se ve** | `media-service` → CloudFront (6.2). |

### ADR-T-M2-05 — Protección del contenido privado

| Opción | Ventajas | Desventajas |
|---|---|---|
| A. URL pública difícil de adivinar | Simple. | Una URL filtrada queda expuesta para siempre. |
| **B. URL firmada con vencimiento corto** | Una filtración caduca en minutos. | Una firma por video, que se pide en lote para toda la página del feed. |

**Decisión:** **B**. **Consecuencias:** la firma por lote se solapa con la precarga, sin afectar ESC-M2-01.
